# 数据备份与恢复

FolioCross 的真实状态都在用户选定的 `workspace/` 中。界面显示的进度来自 SQLite，而不是
Worker 内存。直接关闭桌面窗口不会停止后台调度器和 Worker；重新打开后可以继续查看、暂停或
立即停止。Worker 意外退出也不会抹掉已经提交的段落。

## 安全暂停

“安全暂停”会等待当前模型请求结束，在批次边界停止。再次点击“继续翻译”时，Worker 会跳过
已有译文的段落。“立即停止 Worker”会终止进程并把任务标记为“已中断”；在途请求可能已经
计费，但尚未返回的结果不会写入段落版本。

后台操作记录不会在完成后删除。它们保留开始时间、Worker PID、退出码和错误，便于区分正常完成、
用户立即停止和进程异常退出。调度器进程在队列清空后自行退出；新操作会再次按需启动它。

## 备份

先暂停所有任务，再完整复制 `workspace/`。至少保留：

- `foliocross.db` 以及同目录可能存在的 `foliocross.db-wal`、`foliocross.db-shm`；
- `library/` 中的源书副本和规范化 EPUB；
- `jobs/` 中的任务产物；
- `exports/` 中的成品。

不要只复制数据库后继续让旧工作区运行。恢复时关闭 FolioCross，把整份备份放到一个目录，
再通过 `foliocross --workspace <目录> doctor --json` 检查。数据库迁移会按编号自动补齐。

工作区自己的源书、规范化文件和产物路径以相对路径保存。升级旧数据库时，会根据书籍的
`library/<书籍 ID>/source/` 布局转换原绝对路径，因此备份可以恢复到不同目录。用户明确选择的
工作区外导出位置仍保留为外部位置；API 凭据和外部工具安装位置需要在新机器上配置。

数据库结构变更与版本登记在同一事务内完成，多进程同时启动会依次取得迁移锁。
对于旧版 1–5 号迁移留下的半次升级，程序会核对已有表、索引和列的定义后补齐；遇到不相符的
结构会停止，避免把不明确的数据状态当作升级成功。

## 导出中断

每次导出在工作区中保留独立的成品版本。指定 `--output` 时，该位置得到一份交付副本；
产物记录的 `path` 指向保留版本，`metadata.delivery_path` 指向交付位置。两者最初内容相同，
以后再次导出可以替换交付副本，历史版本不会随之改变。

程序先生成并校验暂存文件，再替换交付文件。写入失败不会破坏已有交付文件。
文件已替换、数据库尚未登记时若程序中断，下次打开工作区会依据持久发布记录补全登记；
外部目录不可用时会保留待恢复记录，之后重试。较早的待恢复任务不会覆盖后来成功的交付副本。

升级旧版导出记录时，仍存在且校验值匹配的文件会复制为独立版本；旧版已经覆盖或遗失的内容
无法凭校验值重新生成，其记录保留为不可用，不再作为可打开的有效产物显示。
失败写入留下的 `.partial` 文件不会显示为成品；排查或清理前应先检查发布记录。

## 不可恢复内容

模型 API Key 在 Windows 凭据管理器或环境变量中，不在工作区备份内。Wenyi 只读迁移也
不会复制 API Key。恢复到另一台机器后需要重新配置凭据，以及 KindleUnpack 或可选 Calibre。
