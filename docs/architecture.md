# 架构与状态

FolioCross 使用“QML 界面—应用服务—SQLite—后台 Worker”的本地架构。界面只进行查询、
人工编辑和任务控制；解析、模型调用、质量修复及导出由独立 Worker 执行。

## 数据身份

每本书以 UUID 标识，以 SHA-256 绑定源文件内容。同名文件不会冲突，路径相同但内容变化
也不会错误续跑。每次翻译任务保存一份不可变配置快照；全局设置变化不会静默改变旧任务。
译前术语表也保存独立的编号快照。后续编辑术语只显示影响范围，不会改变正在运行任务使用的
版本；用户安全暂停并明确“刷新冻结版本”后，新译名才进入之后的模型请求。

SQLite 使用 WAL 和短事务。每次模型响应先落入段落版本表，再更新当前译文和任务进度。
人工编辑产生新的 `manual` 版本并锁定段落，自动修复不能覆盖它。

## 后台调度、Worker 与恢复

桌面端不会把长任务作为自己的子进程持有。开始翻译、译前准备、深度审校、单段重译和重新导出
都会先写入 SQLite 的 `background_operations` 队列，再唤起一个与 GUI 进程分离的本地调度器。
调度器使用单实例文件锁，按照“同时运行的书籍数”启动 Worker；队列、进程号、取消请求、退出码和
错误都持久化。关闭 GUI 不会终止调度器或 Worker，重新打开后通过数据库恢复当前进度和控制入口。

每个任务使用持久锁文件的操作系统文件锁，锁文件本身不会删除。任务的控制意图写入数据库：

- `run`：继续处理未完成段落。
- `pause`：当前请求结束后在批次边界停止。
- `cancel`：停止后保留已经完成的数据。

Worker 每次事件和请求都会刷新心跳。界面关闭后 Worker 继续运行；立即终止 Worker 可能浪费
一个在途请求，但不会丢失此前已经提交的段落。
应用启动时会检查仍标记为运行、但已不再持有操作系统文件锁的任务，并将其改成“已中断”；
继续运行时只处理没有提交译文的段落。工作区数据库、源书副本和导出结果的备份与恢复见
[recovery.md](recovery.md)。

桌面端默认只运行一本书。超过上限的任务以 `queued` 状态持久化，活动任务结束后由后台调度器
自动补位，即使此时 GUI 已关闭；并发上限提高到 2–4 本时同样由这一队列调度。

速度和预计剩余时间使用累计活动时长计算。安全暂停期间的墙钟时间不会进入速度分母，恢复后
不会因为暂停了几小时而得到明显失真的 ETA。

## 翻译并发

译前章节扫描最多四路并发。正文同一章节内部保持顺序，不同章节在全书术语冻结后并发。
请求调度器从两路开始，最高四路；429 会立即降低并发，连续二十次成功后才尝试升档。
输出始终按原章节和段落序号组装，与请求完成顺序无关。

## 扩展边界

格式解析、模型接口和导出器是基础设施适配层。业务层只接触统一章节、段落、术语、问题和
用量模型。PDF、SRT、云服务和聊天运行时不属于当前架构。
